**MendWise** is a research prototype for guideline-grounded wound assessment, built for the La Trobe AI Innovation Ventures Program (SDG 3 / health). It is an Expo app (iOS, Android, and web) that photographs a wound, measures what it can see, asks a short questionnaire, and returns a dressing category plus referral flags.

## The problem

A frontier vision model can look at a wound photo and produce fluent advice. That output cannot be checked: there is no measurement, no pathway id, no rules version, and no audit trail. A clinician (or a university assessor) cannot tell whether the suggestion came from a guideline or from a guess.

MendWise's answer is the opposite shape: **objective measurement + a deterministic, auditable decision**, with AI only supplying inputs and narrating outputs.

## The thesis — deterministic engine, caged AI

Two published guides become code:

- **CWCS** (Australian Government, Dept of Health & Aged Care) — a 26-row lookup: tissue × exudate × infection → primary and secondary dressing categories. Encoded in [`src/decision/engine.ts`](https://github.com/minesh16/woundcare-test/blob/main/src/decision/engine.ts) as `CWCS_PATHWAYS`, currently version `cwcs-2024.1+recon.1`.
- **Mölnlycke 10-step local wound assessment** — referral / escalation triggers (probe-to-bone, ABPI, DFU, LOPS, necrotic tissue, …). Same file, `molnlyckeFlags()`. The manufacturer's name stays in the engine, types, and these docs as **provenance**; it is stripped from patient-facing UI.

AI never emits a pathway. SAM 2 finds a boundary. OpenCV HSI counts tissue inside that boundary. A frontier VLM returns only Zod-validated enums. A frontier LLM writes up facts the engine has already decided. The five invariants that enforce this are [the cage](/docs/architecture/#the-cage).

## Who it is for

| Audience | What they get |
|---|---|
| The person with the wound | Plain-language "what to do / what we saw / dressing type", with a Clinician view one tap away |
| A clinician reviewing the result | Exact clinical terms, pathway id, referral codes, gate codes, `rulesVersion` |
| The venture / Assessment 3 panel | A demonstrable moat: measurement + a unit-tested lookup table, not a wrapper around a chat API |
| Minesh, Raymond, Trang | This site — architecture, modules, operational status, and a hook that nudges the docs when source files change |

## What is actually built

Phases 0, 1, and 2 are **done**, not planned. The SSE orchestrator at `POST /api/v1/assessments/run` already exists (it was scoped as Phase 3 in an earlier plan and shipped with Phase 2). See [Roadmap](/docs/roadmap/) for the split between shipped and next.

Production is not fully wired: the engine, AI Gateway, and SAM 2 run on [mendwise.vercel.app](https://mendwise.vercel.app); **Supabase persistence and audit logging do not**, because `SUPABASE_URL` is missing from the Vercel project. Details: [Production status](/docs/operations/status/).
