We ran the current MendWise pipeline on five public image sets, automatically and with no clinician in the loop: wound outline, size reference, tissue mix and the decision engine. Every number is measured against ground truth, carries a 95% confidence interval, and can be reproduced from the run id with the [evaluation harness](https://github.com/minesh16/woundcare-test/tree/main/eval).

## What it means for the app

<div class="mw-verdict">

### Wound outline

<StatusChip tone="warn">Usable as a draft</StatusChip> The typical outline is good: **median Dice 0.87**, and 59% of drafts reach IoU ≥ 0.7. A minority fail badly, which pulls the mean to **0.68–0.75**, below the 0.80 target. The clinician review step (approve, adjust or redraw) is doing real work and has to stay.

</div>
<div class="mw-verdict">

### Confidence label

<StatusChip tone="risk">Doesn't flag bad drafts</StatusChip> "High" drafts are reliably good (mean IoU 0.81), but **"medium" (0.60) and "low" (0.63) are indistinguishable**, and about 70% of drafts are labelled "low". The label can't tell a reviewer which outlines need a closer look. FUSegNet's second-opinion agreement predicts a bad outline only weakly (AUROC 0.61).

</div>
<div class="mw-verdict">

### FUSegNet fallback

<StatusChip tone="warn">Trade-off to decide</StatusChip> When SAM 3 declines, FUSegNet steps in. That **raises Dice by 0.05** on real wounds, but **nearly doubles false outlines on non-wound images (17% → 31%)**. FUSegNet outlined a "wound" on all 28 non-wound images it was given. It cannot answer "no wound".

</div>
<div class="mw-verdict">

### Coin size reference

<StatusChip tone="risk">Fix before claiming size</StatusChip> On photos with no coin in them, the detector **found a "coin" 23% of the time** (a wall fixture, a fold of fabric). A false coin switches off the "no size reference" safety gate and produces confident-looking cm² areas. How accurately real coins are found and sized is still untested, because no public dataset has them.

</div>
<div class="mw-verdict">

### Tissue mix

<StatusChip tone="risk">Weakest link</StatusChip> Per-class tissue percentages are off by about **21 percentage points** (17 when given the true outline). The dominant tissue type, which drives the dressing pathway, is right **66% of the time, no better than always answering "slough" (67%)**. The clinician's tissue confirmation is essential. The skin-relative classifier is worse, so `TISSUE_RELATIVE` should stay off.

</div>
<div class="mw-verdict">

### Decision engine

<StatusChip tone="ok">Behaves safely</StatusChip> With only a photo to go on, the engine **withheld a dressing pathway on every image**, as designed: exudate and infection are unknown. Whether its pathways and urgent referrals are *correct* is untested, because no public dataset carries those labels.

</div>
<div class="mw-verdict">

### Skin tone

<StatusChip tone="na">No gap detected</StatusChip> Outline quality shows no gap across six skin-tone bands whose confidence interval excludes zero (largest gap 0.08). The bands come from an image-derived proxy, not a clinical skin-tone measure.

</div>

The gate figure (0.749) leaves out the 48 images where FUSegNet drew the outline, because FUSegNet was trained on photos from the same clinic and its scores there are not a fair test. IoU is overlap divided by union. Only "high" separates. A SAM 3 score cut-off of about 0.79 would best separate good outlines (IoU ≥ 0.7) from the rest. That is close to the app's 0.80 band; the medium/low split adds little. An outline takes 6.6 s at the median and 10.8 s at the 90th percentile.

## The FUSegNet backup: better outlines, more false alarms

Paired comparison on the same 1,160 images (`run-20261004-2130-full1-sam3` is SAM 3 without the backup):

| With the backup | Change | 95% CI / test | n |
|---|---|---|---|
| Outline quality (Dice) | **+0.048** | [+0.032, +0.064], paired bootstrap | 436 expert-outlined |
| False outlines on non-wound images | **17% → 31%** | McNemar p < 0.0001 | 154 non-wound |

In the app a clinician reviews every outline, so a false outline is a prompt to reject rather than a wrong answer. But it is the model suggesting a wound where there is none. Options for the team: keep FUSegNet as a second opinion only, or accept its fallback outline only when the plausibility checks pass by a wider margin.

The coin result matters most. A reported coin switches off the "no size reference" gate, so 23% of coin-free photos would have been sized and passed on as if measured. ## How this was measured

- Each photo went through the app's own code in-process: segmentation (SAM 3 on fal.ai, FUSegNet on Modal, colour-threshold fallback), coin and size measurement, tissue classification, and the deterministic CWCS / Mölnlycke engine. The harness imports these functions unchanged. A parity check confirms it reaches the same engine result as the app's own orchestrator.
- The model's first outline was used as returned, with no clinician step. In the app a clinician approves or corrects it, so these numbers describe the draft, not the final assessment.
- Proportions use Wilson intervals. Means use a seeded bootstrap with 2,000 resamples. Paired comparisons use McNemar's exact test and a paired bootstrap.
- Metrics where FUSegNet drew the outline on data from its own training clinic are reported separately and never quoted as generalisation.

| Dataset | In run | Used for | Notes |
|---|---|---|---|
| FUSeg 2021 (AZH Wound Center) | 400 | Outline vs expert masks | Same clinic as FUSegNet's training data |
| AZH wound classification | 400 | Wound types, real non-wound patches | Same clinic |
| Medetec wound database | 200 | 16 wound categories, behaviour only | No outlines available |
| DFUTissue | 110 | Tissue mix vs expert labels | Same clinic |
| Synthetic skin | 50 | Non-wound images | Generated; an easy negative (0% false outlines) |

<Aside type="note" title="Not covered by public data">
Exudate, infection, ischaemia and referral labels; photos with a coin or a measured wound size; clinician review. WoundcareVQA, the one public source of exudate and infection labels, requires registration and was excluded. These need the team's own labelled photos, which can be onboarded through the same harness (see `eval/README.md`).
</Aside>

## Quoting these numbers

- Cite the run id with any number, and say it is public-data, model-draft performance before clinician review.
- Fair claims: segmentation measured at scale with confidence intervals; median outline overlap 0.87; the engine withholds a pathway when inputs are missing; three safety issues found and quantified.
- Not supported yet: accuracy of dressing recommendations or referrals, coin-based wound sizing, and automated tissue classification.

```text
MendWise eval harness, run-20261004-2052-full1 (4 Oct 2026), 1,160 public images; SAM 3 → FUSegNet chain,
image-only policy; 95% CIs. FUSegNet metrics on AZH-clinic data are in-distribution and excluded from

```
